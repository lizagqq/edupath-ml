# Локальные данные ASSISTments

Исходный CSV, очищенные ответы и SQLite не включены в Git. Рабочие файлы на исходном компьютере сохранены; `.gitignore` только исключает их из публикации.

## Источник и условия

Использован **ASSISTments Skill Builder 2009–2010, corrected collapsed**:

- [Страница конкретной версии](https://sites.google.com/site/assistmentsdata/home/2009-2010-assistment-data/skill-builder-data-2009-2010).
- [Общие условия и требования к обезличенным данным](https://sites.google.com/site/assistmentsdata/).
- [Актуальный каталог исследовательских данных](https://sites.google.com/view/e-trials/data-sets/publicly-available-data-sets).

На странице указаны исправленная версия и требование цитировать точный URL и публикацию Feng, Heffernan, Koedinger (2009), User Modeling and User-Adapted Interaction, 19, 243–266. Общая страница требует сообщать об обнаруженной идентифицирующей информации, удалять её и не использовать. Подробные условия вынесены в Google-документ; автоматическое чтение этого документа 17.11.2026 было недоступно (401). Поэтому не подтверждена отдельная лицензия на повторное распространение именно этой выгрузки. Лицензия CC BY-NC 4.0 другого набора FoundationalASSIST не переносится на ASSIST 2009–10.

Это не утверждение, что скачивание и исследовательское использование запрещены. Решение для этого репозитория — не распространять заново исходные и производные записи учеников, а дать ссылку на владельца. Приватность репозитория сама по себе не устанавливает права на распространение данных.

## Запуск из новой копии без обучения

### Вариант A: перенести собственную готовую базу

На исходном компьютере база расположена в `data/demo/edupath.db`. Перенесите её на свой MacBook через USB, AirDrop или другой доступный вам защищённый канал и положите в **такой же относительный путь** нового клона. Базу в Git добавлять не нужно. Исходный CSV для обычного запуска после этого не требуется.

Это перенос своей рабочей базы на свой компьютер, а не предложение разместить её в общем доступе. Не переносите токены, `.venv` или настройки учётных записей.

### Вариант B: восстановить только базу по официальному CSV

1. Ознакомьтесь с условиями владельца, скачайте исправленный **collapsed** CSV по официальной странице.
2. Сохраните его как `data/raw/skill_builder_data_corrected_collapsed.csv`.
3. Из корня репозитория выполните:

```bash
python scripts/prepare_database.py
```

Скрипт только проверяет/очищает CSV и создаёт SQLite с существующими 23 материалами и пятью связями. Он **не обучает модель, не меняет отчёты и не перезаписывает существующую БД**. При другом файле или уже существующей базе он остановится. Для отдельной проверочной базы можно указать `--destination /путь/к/новой/edupath.db`.

Ожидаемый SHA-256 CSV:

```text
162ef8d2d28bcbfea6591a282994062bd8d5eaa00636544292a0d268dca6e5da
```

Файл: 64 412 812 байт; 346 860 исходных строк; после очистки — 283 105 ответов, 4163 ученика и 149 ID навыков. Эта контрольная сумма относится к использованному локальному файлу; независимого хеша издателя нет.

`build_project.py` служит для полного исторического воспроизведения с обучением и пересозданием базы. Для запуска существующей модели его не используйте.
