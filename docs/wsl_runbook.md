# Запуск и ручная проверка EduPath ML 0.2.0 в Ubuntu WSL2

Все команды выполняются из `/home/liza/coursework-ml`. Используются готовые SQLite и модель. `scripts/build_project.py` для открытия приложения не запускайте: он пересоздаёт данные и обучает модель.

## 1. Остановить старые процессы

В терминалах старых API и Streamlit нажмите Ctrl+C. Если процесс запускался в другом терминале, найдите его командой `pgrep -af 'uvicorn|streamlit'` и остановите именно соответствующий процесс. Ошибка «address already in use» означает, что порт ещё занят; смена страницы браузера старый сервер не обновляет.

В существующем виртуальном окружении зависимости уже установлены. При необходимости: `.venv/bin/python -m pip install -r requirements.txt`.

## 2. Запустить API — терминал 1

```bash
cd /home/liza/coursework-ml
.venv/bin/python -m uvicorn src.api.app:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/students/79021/trajectory > /tmp/edupath-plan.json
.venv/bin/python -c 'import json; p=json.load(open("/tmp/edupath-plan.json")); print(p["contract_version"], p["material_count"], [x["skill_id"] for x in p["trajectory"]])'
```

Ожидаются `/health`: `app_version="0.2.0"`, `trajectory_contract_version=2`; траектория: `2 23 ['292', '290', '2_37_70', '39', '299']`. Если поля отсутствуют, всё ещё отвечает другая версия сервера. Проверьте команду запуска, каталог и EDUPATH_API. Swagger: http://127.0.0.1:8000/docs.

## 3. Запустить интерфейс — терминал 2

```bash
cd /home/liza/coursework-ml
EDUPATH_API=http://127.0.0.1:8000 .venv/bin/python -m streamlit run ui/app.py --server.address 127.0.0.1 --server.port 8501
```

Откройте http://127.0.0.1:8501. В навигации должны быть только «Профиль ученика», «Анализ знаний», «План обучения». При старых названиях обновите страницу и проверьте, что открыли нужный порт и остановили старый Streamlit.

## 4. Автоматическая проверка реального HTTP

После запуска обоих процессов:

```bash
.venv/bin/python scripts/smoke_http.py
.venv/bin/python scripts/smoke_streamlit.py
```

Первый скрипт проверяет версии, Swagger, контракт, три маршрута, 23 материала, пустой маршрут и 404/422 через настоящий HTTP. Второй открывает три страницы и все шаги трёх учеников через AppTest с ответами реального API. Отчёты создаются только после успешного прохождения: `reports/http_integration.json` и `reports/streamlit_apptest.json`. AppTest и при живом HTTP не является браузерным визуальным тестом.

Без доступных сокетов:

```bash
PYTHONPATH=tests .venv/bin/python -m unittest test_core.RecommendationTests test_core.ServiceTests test_api.APITests test_ui_presentation.PresentationTests test_learning_contract.LearningContractTests -v
.venv/bin/python scripts/smoke_asgi.py
.venv/bin/python scripts/smoke_streamlit.py --asgi
```

Последняя команда подаёт в UI сериализованные ответы настоящего FastAPI внутри процесса. Для среды без FastAPI остаётся `--local-service`, но эта проверка не охватывает его маршрутизацию. В ASGI используется прямой вызов обработчиков вместо стандартного пула потоков; HTTP этим не подтверждается.

## 5. Проверка в браузере

Проверьте следующие сценарии и сохраните реальные скриншоты в `reports/screenshots/`:

1. Ученик 79021, профиль: 1061 ответ, 93 темы с ответами и 56 с минимум тремя ответами. Показатель правильных ответов — доля по истории, а не оценка освоения. Видны три сигнала и кнопка открытия плана.
2. Анализ: прошлые результаты и прогноз разделены, у каждой записи указано число ответов. У круговых диаграмм разные подписи записей; точные ID доступны в подробностях. Откройте блоки достаточной, малой и нулевой истории.
3. План 79021: повороты → отражение → круговые диаграммы → площадь круга → поверхность цилиндра. У площади круга явно указана подготовительная роль перед цилиндром. Откройте каждый шаг, прочитайте пример, раскройте ответы и решения.
4. Отметьте первый шаг, перейдите дальше, смените раздел и вернитесь. Отметка должна сохраниться в сессии. У другого ученика она не должна появиться. При этом прогнозы не меняются.
5. У 75169 план содержит два шага, у 78970 — четыре. Проверьте три раздела для каждого. В плане отдельно раскрываются отложенное повторение и затруднения без материала. Нет вкладки «Качество модели».
6. В инструментах разработчика браузера задайте размеры области просмотра: 1440×900, 768×1024 и 390×844. У профиля на широком экране две карточки в строке, на узком — одна. Проверьте читаемость названий, перенос кнопок и навигации, отсутствие горизонтальной прокрутки всей страницы. Таблица может иметь собственную внутреннюю прокрутку.
7. На узкой ширине откройте/закройте боковую панель, выберите длинное название темы, последний шаг и ответы на задания. Убедитесь, что текст не обрезан, а кнопки доступны.

Визуальная адаптация после этих изменений в среде разработки не проверена: браузер отсутствует, сокеты запрещены. Пользовательская проверка предыдущей версии и нынешние AppTest/ASGI — разные этапы.

## Дополнительные материалы эксперимента

ML-метрики сохранены в `reports/experiment.json`, `reports/model_metrics.csv` и `docs/ml_experiment.md`, доступны также через `/model/info`. MLflow для пользовательского интерфейса не требуется. Регистрация готовых результатов при необходимости выполняется отдельно по существующей инструкции и не входит в обязательную проверку этого обновления.
