# Публикация EduPath ML в приватный GitHub

Целевой адрес: **https://github.com/lizagqq/edupath-ml**. Указание адреса не означает, что репозиторий уже создан: подтверждённый результат загрузки записывается отдельно в `_publication/github_result.json`.

## Что подготовлено

- `.gitignore` исключает окружения, кэши, секреты, исходные/обработанные данные учеников, базы, архивы, личные Word-файлы и сторонние PDF. Локальные файлы не удаляются.
- Исходный код, модель JSON, тесты, зависимости, агрегированные отчёты и технические Markdown-документы составляют публикационную копию.
- `prepare_database.py` восстанавливает только БД из известного CSV без обучения и без перезаписи существующей базы.
- `audit_publication.py` проверяет состав и все доступные Git-блобы на признаки секретов, запрещённые файлы и большие объекты. Значения найденных секретов не печатаются. Это эвристическая проверка, а не гарантия обнаружения любых возможных секретов.
- `prepare_github_release.py` создаёт изолированную копию, проверяет её, делает локальный служебный коммит и ZIP. Исходная `.git` не изменяется.
- `publish_github.py` после авторизации проверяет аккаунт, приватность, состояние удалённой истории и загружает без force push.

## Ограничения этой среды

При подготовке 17.11.2026 `.git` рабочего каталога оказалась пустой и доступной только для чтения. Git не распознал существующий репозиторий/историю. GitHub CLI отсутствует, авторизационных переменных и настроенного credential helper нет. Запросы Python к api.github.com не прошли из-за сетевых ограничений. Подключение GitHub предложено отдельно; пока оно не подтверждено, доступ к аккаунту не предполагается. Проверить существование приватного репозитория без авторизации невозможно.

Поэтому чистая локальная Git-копия создаётся в `_publication/edupath-ml`, рядом — `_publication/edupath-ml-source.zip` и аудит. Это отдельная подготовленная копия существующего проекта, а не пересоздание приложения. Служебный локальный коммит имеет автора `EduPath snapshot <snapshot@localhost>`: подтверждённого email владельца в окружении нет. При реальной публикации скрипт получает login/id из GitHub и использует адрес noreply владельца, не меняя глобальную конфигурацию Git.

## 1. Подготовить копию, если её ещё нет

Из исходной папки:

```bash
cd /home/liza/coursework-ml
.venv/bin/python scripts/prepare_github_release.py
```

Скрипт не перезаписывает существующий `_publication/edupath-ml` или ZIP. Для нового снимка укажите новый каталог:

```bash
.venv/bin/python scripts/prepare_github_release.py --destination _publication/revision-2/edupath-ml
```

Для публикации такой копии передайте тот же путь через `publish_github.py --snapshot ...`. Данные и токены не добавляйте в снимок вручную.

## 2. Авторизоваться в обычной Ubuntu

Если GitHub CLI не установлен:

```bash
sudo apt update
sudo apt install gh git
```

Выполните:

```bash
gh auth login --hostname github.com --git-protocol https --web
gh auth status --hostname github.com
gh api user --jq .login
```

Откройте указанный CLI адрес в браузере, войдите в **lizagqq**, введите одноразовый код и завершите подтверждение. Последняя команда должна показать lizagqq. Пароли, одноразовые коды и токены не нужно присылать в чат или сохранять в проект. Документация: https://cli.github.com/manual/gh_auth_login.

Альтернатива — подключить GitHub к сессии с правами на нужный аккаунт. Одного разрешения на чтение недостаточно для создания приватного репозитория и отправки файлов; фактические возможности проверяются после подключения.

## 3. Завершить публикацию

После успешного входа:

```bash
cd /home/liza/coursework-ml
.venv/bin/python scripts/publish_github.py
```

Скрипт действует так:

1. Проверяет аккаунт lizagqq и аудит подготовленного снимка.
2. Проверяет наличие репозитория; создаёт его приватным только при подтверждённом 404. При сетевой ошибке не пытается угадать состояние.
3. Если репозиторий уже публичный, останавливается, не меняя настройки.
4. Клонирует существующую историю и сканирует её. Ничего не переписывает и не удаляет.
5. Для пустого репозитория публикует main. Для непустого создаёт отдельную ветку `edupath-publication-...` на основе существующей истории; исходная ветка по умолчанию остаётся без изменений. Так не перезаписываются чужие изменения. В этом случае полный проект смотрите в созданной ветке; её можно отдельно просмотреть и объединить обычным способом.
6. Делает коммит с проверенным GitHub login/id, выполняет обычный push, сравнивает SHA удалённой ветки и проверяет приватность.

Подтверждение появится в `_publication/github_result.json`. Не используйте force push и не загружайте ZIP в Git вручную: ZIP служит для переноса проверенного исходного состава.

## 4. Скачать на MacBook

После подтверждённой загрузки:

```bash
brew install python@3.12 git gh
gh auth login --hostname github.com --git-protocol https --web
gh repo clone lizagqq/edupath-ml
cd edupath-ml
```

Если публикация ушла в отдельную ветку существующего репозитория, переключитесь на имя из `github_result.json`: `git switch --track origin/имя-ветки`.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Перенесите собственную готовую `data/demo/edupath.db` в ту же папку клона. Либо загрузите официальный CSV и выполните `.venv/bin/python scripts/prepare_database.py` по [инструкции данных](../data/README.md). Без базы профиль ученика открыть нельзя; это ожидаемое условие безопасного состава репозитория.

Терминал 1:

```bash
.venv/bin/python -m uvicorn src.api.app:app --host 127.0.0.1 --port 8000
```

Терминал 2, та же папка:

```bash
EDUPATH_API=http://127.0.0.1:8000 .venv/bin/python -m streamlit run ui/app.py --server.address 127.0.0.1 --server.port 8501
```

Браузер: **http://127.0.0.1:8501**. Модель загружается из JSON; обучение не требуется. Актуальные три раздела и материалы не изменены подготовкой GitHub. Сами macOS и браузерное отображение на MacBook в ограниченной среде не проверяются.

## Проверка новой копии

Для локальной проверки клонируется именно подготовленный Git-снимок, а не вся исходная папка с окружением и данными. После восстановления БД по оригинальному CSV проверяются связанные тесты и FastAPI→Streamlit внутри процесса. Результаты фиксируются в локальном `_publication/fresh_clone_check.json`. Эта проверка не означает, что GitHub-загрузка или внешний HTTP уже состоялись, и использует существующее Python-окружение для зависимостей: новую установку из интернета среда не подтверждает.
